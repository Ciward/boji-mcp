# Boji 是怎样记下一餐的

Boji 是一个个人自托管的饮食与健康账本。你可以把午餐照片交给已连接的 AI 助手，吃完再告诉它剩了多少。打开手机浏览器，这两次对话应当对应日记里的同一顿饭。以后换用另一个支持远程 MCP 的助手，只要授权它访问同一台 Boji 服务，它就能查询这份账本。

如果你只想手动记录，Web 日记本身就能添加和编辑餐食。喜欢用对话记账的人可以接入助手；希望把步数和睡眠也放在当天日记里的人，可以再配置健康数据来源。这三个入口可以分别使用。[启动说明](../README.md)

## 从早餐标签到晚间回顾

以下是一组虚构的记录，用来说明数字如何进入账本。

**早餐，你第一次记录一种酸奶。** 包装标注每 100 克含 80 千卡、蛋白质 4 克。你告诉助手这杯有 150 克。助手先获取账本时区和日期，再查个人食物库；确认品牌、口味、规格后，可以把标签数值和参考份量保存下来。这杯的整份估算为 120 千卡、蛋白质 6 克。标签没有提供的膳食纤维可以留空。

**吃完，你补充“刚才那杯只吃了三分之二”。** 助手读取原早餐的当前版本，把这项食物的实际食用比例改为三分之二。服务端以整份数值计算，本次贡献 80 千卡、蛋白质 4 克。日记里仍只有一条早餐，修订历史保留先前记录。若你也在浏览器里改过这顿饭，旧版本写入会遇到冲突，助手应重新读取后合并。

**午餐，你拍了一盘散装饭菜。** 宿主助手根据照片和你的说明估算份量，将可判断的营养、估算依据和不确定性写进此次餐食。下次再吃相同菜名时，助手还应核对餐厅和做法。食物库适合保存经确认的常吃菜品；如果以后厂家换了配方，更新基线会产生新版本，以前的早餐保留当时的数值。[食物库如何引用和换算](implementation/个性化食物库.md)

**晚上，你打开当天日记。** 可以查看已记录餐食的营养合计、缺测项，以及已接入来源的健康摘要。若设备下午才上传过数据，要结合覆盖时间解读当天步数。漏记的晚餐仍然是漏记；即使已有运动消耗，也无法据此推断全天能量差。Web 提供七日饮食趋势，MCP 可按最近 1 至 90 天查询记录趋势。

## 数据经过哪些地方

| 入口 | 谁处理输入 | 在 Boji 中产生什么 |
| --- | --- | --- |
| 对话里的照片、标签和份量说明 | 你选用的 AI 宿主负责识别、估算和必要的资料查找，使用 OAuth 授权的 MCP 工具读写 | 结构化餐食、依据、参考份量、食用比例和可选的食物库版本引用 |
| 浏览器日记 | React 页面通过登录会话调用 REST API | 同一份餐食或食物库记录及其版本历史 |
| Apple Health XML、Health Auto Export 或自定义来源 | Boji 校验格式和来源，统一日期、单位并识别重传 | 健康样本、导入回执、来源覆盖信息和按日汇总 |

Node.js 服务把 Web 和 MCP 的餐食读写交给同一个 `Store`。SQLite 同时保存账本、健康样本与授权状态。写入请求携带幂等键，遇到超时可用相同键和相同内容重试。MCP 返回 `persisted: true` 是助手向你确认保存的依据。需要对接自己的客户端时，可直接查看[API 契约](implementation/API契约.md)和[授权契约](implementation/授权契约.md)。

## 连接 Apple 健康后能看到什么

首次试用可以从解压后的 `export.xml` 开始。先在 Web 创建 Apple XML 来源，再选文件导入；超过 20 MiB 的完整文件可以使用本地导入命令。XML 路径能接收步数、活动能量、基础能量、体重、睡眠和锻炼时长。另一条路径是让配置好的 Health Auto Export 向专属地址上传 JSON；它支持前五类中的指定格式，睡眠需为聚合数据，`data.workouts` 当前不会进入账本。

同一天既有手表也有手机记录时，Boji 会为每个指标选择来源和数据表示，再按规则处理重叠。睡眠按醒来时所在的本地日期归属，体重取最近一次测量。上传回执给出新增、更新或跳过的数量。来源状态能说明服务器收到了什么，手机端的权限、后台运行和下一次上传仍由设备与桥接应用控制。[健康格式、来源选择与覆盖规则](implementation/健康接入契约.md)

## 谁能看到什么，如何带走自己的记录

这版按**单人账本**设计。Web 管理密码、AI 客户端的 OAuth 授权及各设备的来源令牌分别用于登录、工具调用和上传。给设备配置来源令牌即可向该来源上传；管理密码应由账本所有者保管。面向互联网部署时，需要为公开地址配置 HTTPS 和反向代理。[部署与备份恢复](implementation/接入与部署.md)

餐食工具接收结构化字段。把照片发给云端助手时，照片和对话会先交给该宿主处理，授权查询的记录也可能进入它的上下文。自托管可以让你选择账本的服务器、备份地点和授权对象；希望减少发给外部服务的信息时，可以直接使用 Web 手工记录。

日记中的删除可通过回收站恢复，历史快照仍会保留。需要取走数据时，JSON 导出包含餐食、食物库、历史和健康数据。需要迁移整套服务时，使用 SQLite 在线备份并按部署文档恢复；数据库备份还包含授权记录，应当按私人凭据的标准保管。

## 第一版的使用范围

适合先用一顿饭走完“记录、补充剩余、核对汇总”，确认助手和网页展示同一条记录，再决定是否接入个人历史健康数据。仓库提供的是自托管服务、浏览器界面和 MCP 工具。原生 iOS 客户端、服务内模型推理和主动定时提醒属于后续方向。对于新的 AI 宿主或手机桥接配置，兼容性最终要以一次实际授权、一次写入和一次回读为准。
