# 健康接入契约

版本：v0.1

本契约对应 `src/health.ts` 的 `HealthService`。它只负责健康来源、SQLite 持久化、健康样本规范化和日汇总。HTTP、MCP、餐食和认证宿主由调用方负责；调用方应把这里抛出的 `HealthError.status` 和 `HealthError.code` 转成外部错误响应。

## 集成签名

```ts
import type { DatabaseSync } from 'node:sqlite';
import { HealthService } from './health.js';

const health = new HealthService(db as DatabaseSync, timezone);
const { source, token } = health.createSource({ name, kind });

health.authenticateSource(source.id, token);
health.importXml(source.id, xmlText);             // only apple_xml
health.ingestAutoExport(source.id, parsedJson);  // only health_auto_export
health.ingestGeneric(source.id, parsedJson);     // only generic
health.dailySummary('2026-10-20');
health.exportData();
```

`kind` 只能是 `apple_xml`、`health_auto_export`、`generic`。来源创建时返回一次随机 64 个十六进制字符的 token；数据库只保存 `sha256(source_id + ':' + token)`，导出和来源列表都不会返回明文或哈希。停用来源会拒绝后续接收，撤销来源会清除 token 哈希并且不能直接重新启用。

健康表全部使用 `health_` 前缀：`health_migrations`、`health_meta`、`health_sources`、`health_samples`、`health_tombstones`、`health_runs`。服务只创建和迁移这些表，不修改 `profiles`、`meals` 或其他业务表，并可嵌套在调用方 SQLite 事务中。

## HTTP 调用边界

调用方应对上传请求先执行边界限制：XML 请求体最大 20 MiB，JSON 请求体最大 2 MiB。`HealthService` 对直接调用也会再次检查大小、结构、层级、数量、时间、单位和数值，因此不能通过绕过 HTTP 直接调用来放宽契约。

20 MiB 是 HTTP 单批上限。完整 Apple 导出可通过已实现的本地 CLI 导入，整文件没有 20 MiB 上限：

```bash
npm run import:health -- \
  --file /absolute/path/export.xml \
  --database /absolute/path/boji.sqlite \
  --source 已创建的apple_xml来源UUID \
  --timezone Asia/Shanghai
```

先在 Web/API 创建 `apple_xml` 来源，再使用返回的 UUID。CLI 直接使用本地数据库访问权限，要求现有数据库与启用的来源；不接收来源 token，也不会新建空数据库掩盖路径错误。不修改 HTTP 20 MiB 上限或包脚本。

文件导入有两个阶段：

1. 第一阶段按 64 KiB 读取 UTF-8 文件，通过与 HTTP 相同的 SAX 安全验证器校验完整根、DTD、层级、实体和标签；按顶层元素重新编码为独立 `HealthData` 文档，保留属性、子元素和 `MetadataEntry`。每批目标上限为 4 MiB 或 2,000 个顶层元素；单个元素不可切开，最多允许 16 MiB，因此单批仍小于服务的 20 MiB 限制。每批在独立内存库里调用真实 `HealthService.importXml` 校验后回滚，写入 0700 临时目录中的 0600 文件。直到全文件语法和所有批次数据都通过，目标库仍未发生写入。临时目录需有容纳规范化 XML 的磁盘空间，内存只持有有限批次和批次清单。
2. 第二阶段校验暂存批次 SHA-256，再逐批调用目标来源的 `importXml`。每批独立提交。第一阶段失败时抛出安全错误且零写入；第二阶段失败或可处理的终止信号返回 `partial` 和已提交计数，已经提交的批次保留。成功返回 `completed`。两种结果均有 `file_sha256`、`bytes_read`、`validated_batches`、`committed_batches`、`replayed_batches` 和 `resumable:true`。

运行结束或可处理异常后删除暂存目录。操作系统强制杀进程/断电可能留下 0700 暂存目录；其内容是敏感健康 XML，不进入代码仓库。重试同一文件、来源和 CLI 版本会生成稳定批次，数据库的批次 hash/样本键可恢复进度；重放批次的历史 `inserted` 不计入本次新增数量。重试会重新验证全文件，不是任意字节偏移续传。第一阶段与文件读取并不产生“完整覆盖”的声明，`coverage_complete` 仍为 false。

CLI 的标准输出为单条最终 JSON；标准错误为仅含批号、run ID、重放状态的进度 JSON。失败/partial 的退出码为 1，completed 为 0。不输出原始 XML、名称、token 或完整异常堆栈。当前自动化测试以超过 20 MiB、3,000 条合成样本验证大文件导入、首批提交后中断、重跑去重和末尾坏记录零写入。
HealthService 接入方法不执行网络请求、不读取本地路径、不解析 URL，也不把原始健康正文写入错误信息。服务端应只在来源 token 验证成功后调用对应 `ingest*` 方法。

## Apple Health XML

Apple 的健康导出是 XML 文件。常见真实 `export.xml` 顶部包含：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE HealthData [
  <!-- HealthKit Export Version: ... -->
  <!ELEMENT HealthData (... )>
  <!ATTLIST HealthData locale CDATA #REQUIRED>
  ...
]>
<HealthData locale="en_US">
```

实现使用 `saxes` 流式解析，不使用正则表达式解析记录。为了兼容该标准内部声明，解析器允许以下受限 DTD：根名为 `HealthData`；内部子集只包含注释、结构性的 `ELEMENT` 和 `ATTLIST` 声明；属性声明只允许 `CDATA` 与 `#REQUIRED/#IMPLIED`。允许 `<!DOCTYPE HealthData>` 没有内部子集。

以下内容一律拒绝：

- `ENTITY`、参数实体、用户自定义实体引用和属性默认值；XML 预定义转义（例如 `&amp;`）和字符引用由 SAX 正常解析；
- `SYSTEM`、`PUBLIC`、外部子集、外部资源或外部引用；
- 条件段、处理指令、CDATA 文本、未知根元素、未知子元素和意外命名空间；
- 无时区偏移的时间、非法日期/时分秒、结束早于开始、负数或不支持单位。

当前 XML 支持：

| Apple 类型 | 规范指标 | 规范单位 | 聚合方式 |
| --- | --- | --- | --- |
| `HKQuantityTypeIdentifierStepCount` | `steps` | `count` | 样本求和 |
| `HKQuantityTypeIdentifierActiveEnergyBurned` | `active_energy` | `kcal` | 样本求和 |
| `HKQuantityTypeIdentifierBasalEnergyBurned` | `basal_energy` | `kcal` | 样本求和，支持 `kJ` 转换 |
| `HKQuantityTypeIdentifierBodyMass` | `weight` | `kg` | 最新测量 |
| `HKCategoryTypeIdentifierSleepAnalysis` | `sleep` | `hr` | 睡眠区间并集 |
| `Workout` | `workout` | `min` | 时长求和 |

睡眠按结束时间所在的用户本地日归属，保留原始起止时间；`InBed` 和 `Awake` 不计入睡眠，重叠的 asleep 区间只计一次。运动时长、能量和体重的原始值、原始单位、来源名称、设备和 Apple 类型保存在规范样本中。运动内部能量统计不再次加入 `active_energy`。

无 `uuid` 的 XML 样本使用来源、设备、指标、起止时间、值和单位组成稳定指纹。带 `HKMetadataKeySyncIdentifier` 或 `uuid` 时优先使用稳定外部标识。重复导入同一内容返回同一回执；更换仅导出封装信息（例如 `ExportDate`）不会产生新样本。

## Health Auto Export JSON

官方 Health Auto Export 当前文档描述的包装是 `data.metrics`，每个指标包含 snake_case 的 `name`、`units` 和 `data`；普通数据点使用 `qty`、带时区偏移的 `date` 和可选 `source`。睡眠聚合使用 `date`、`totalSleep`、`sleepStart`、`sleepEnd` 等字段；未聚合的睡眠片段不在当前可靠支持范围内。支持的映射为：

- `step_count` → `steps` / `count`
- `active_energy` → `active_energy` / `kcal`
- `basal_energy_burned` → `basal_energy` / `kcal`，支持 `kJ`
- `weight_&_body_mass` → `weight` / `kg`，也支持 `g`、`lb`
- 聚合 `sleep_analysis` → `sleep` / `hr`

未知指标和不支持的睡眠片段会跳过并在回执中计数。`data.workouts` 等非 metrics 分区当前不导入，也不计入 metrics 的跳过数。空批次、只包含未知指标的批次不会产生样本，也不会把覆盖标记为完整；`coverage_complete` 当前始终为 `false`，因为 HTTP/桥接批次没有声明完整历史镜像。

Auto Export 的普通时间点使用 `metric + 规范化UTC时间点 + sourceName` 作为聚合桶；睡眠使用 `metric + 日历日 + sourceName`。同一来源、指标、桶和来源名称再次发送新内容时替换原桶，不追加累加。官方格式未给普通桶提供时长或 revision；同一来源应固定导出时间粒度，不混发小时桶和日桶。完全相同历史 payload 被识别为重试，不重新应用旧桶；无法从供应商格式判断一个全新 payload 是迟到旧版本还是最新修订。来源名称是桶键的一部分，因此同一日期的 Watch 与 iPhone 桶不会无条件相加；日汇总先选来源和表示形式，再按来源优先级与非重叠规则计算。

## Generic JSON

Generic 请求为：

```json
{
  "request_id": "optional-stable-request-id",
  "samples": [
    {
      "external_id": "optional-source-id",
      "metric": "steps",
      "record_kind": "sample",
      "start_at": "2026-10-20T08:00:00+08:00",
      "end_at": "2026-10-20T09:00:00+08:00",
      "value": 100,
      "unit": "count",
      "source_name": "device",
      "device": "watch",
      "revision": 1
    }
  ],
  "deleted": [{ "external_id": "source-id", "revision": 2 }]
}
```

`external_id + revision` 支持修订和 tombstone。没有外部 ID 时使用稳定内容指纹；修改测量或 aggregate 时必须发送稳定 `external_id` 和递增 `revision`，否则变化后的内容会成为新样本。旧版本不会覆盖新版本；同一版本不同内容会返回冲突并回滚整批。已收到删除 tombstone 后的旧样本不会复活。可选本地 ignore 只改变 Boji 展示和汇总，不改写来源值，且来源重传不会清除它。

## 事务、幂等和回执

每个 HTTP/服务批次接收先完成内存校验，再在 SQLite savepoint 中写入样本、tombstone、来源状态和 `health_runs`。任何支持记录的时间、单位或数值验证失败都会让整批回滚；跳过未知指标属于成功接收，回执中的 `skipped` 和 `unsupported_metrics` 必须被调用方展示或记录。

`request_id` 仅适用于 Generic；同一来源同一请求 ID 的不同 payload 返回 `IDEMPOTENCY_CONFLICT`。所有来源同时使用 payload hash 做批次重放识别。回执包含：

```ts
type HealthReceipt = {
  status: 'persisted';
  run_id: string;
  source_id: string;
  received_at: string;
  replayed: boolean;
  inserted: number;
  updated: number;
  unchanged: number;
  deleted: number;
  skipped: number;
  rejected: number;
  supported: number;
  unsupported_metrics: number;
  coverage_start: string | null;
  coverage_end: string | null;
  coverage_complete: false;
  data_revision: number;
};
```

## 跨来源和同源去重

`dailySummary(date)` 先过滤启用且未忽略、未删除的样本，再对每个指标选择一个来源连接和一种表示形式。选择顺序是：覆盖末端和变更序列较新的连接，其次稳定 source ID；同一来源内可通过 `setSourcePriority(sourceId, ['Watch', 'iPhone'])` 配置来源名称优先级，未配置时使用 Watch 高于 iPhone 的默认倾向。

选择为样本流时，优先流的时间区间保留，后续设备只有完全不重叠的区间可以贡献；部分重叠的记录整体舍弃，不按时间比例臆造步数。重叠记录被计入 `discarded_overlap_samples`。选择为 aggregate 流时只选择一个原始 sourceName 的桶，缺少桶时长时不混加其他设备桶，避免把 Apple XML 的样本和桥接端的日桶相加。跨来源会保留 `available_sources`、`source_id`、`source_kind`、`contributing_source_names`、覆盖时间和 `aggregation` 元数据，使“缺失”与“值为零”可区分。

累计样本和普通桶按开始时间对应的用户本地日归属，不推断跨日样本内的分布；睡眠按醒来日归属。体重取最新测量。默认 Watch/iPhone 优先级根据原始来源名称或设备文字识别；不能还原 Apple Health 用户授权和设备排序，名字被本地化时应明确设置 `setSourcePriority`。

当前策略是确定性的来源选择策略，不是医学真值合并。服务不推断总能量平衡，也不把多个来源都加进一个指标来制造完整性。

## 核验来源与限制

核验日期：2026-10-20。下列是格式来源，不构成个人手机自动上传验收。

- HealthyApps 官方 [Health Metrics JSON](https://help.healthyapps.dev/en/health-auto-export/export-format/health-metrics/)：普通 `qty/date/source`、`weight_&_body_mass` 与聚合睡眠字段。
- HealthyApps 官方 [JSON Export Overview](https://help.healthyapps.dev/en/health-auto-export/export-format/)：`data.metrics` 包装和时间格式。
- HealthyApps 官方 [Supported Data](https://help.healthyapps.dev/en/health-auto-export/getting-started/supported-data/)：`Basal Energy Burned`；结合官方 snake_case 命名规则映射为 `basal_energy_burned`。
- Apple 官方 [Share your data in Health](https://support.apple.com/guide/iphone/share-your-health-data-iph5ede58c3d/ios)：确认“导出全部健康数据”产物为 XML；未提供逐版 DTD 格式承诺。
- 原导出文件作者的一手 [Apple Health XML 分析及 export.xml 头部](https://www.tdda.info/in-defence-of-xml-exporting-and-analysing-apple-health-data)：证实真实导出含 `HealthData` 内部结构 DTD。当前夹具依据该结构手工编写，所有数据均为合成，未复制个人健康记录。

已验证的是本地服务、存储和文件导入；尚未验证用户设备上的 Health Auto Export 实时推送、手机授权/后台交付、所有 iOS 版本新增元素。未知结构会明确失败，未知 Record 类型会跳过计数。DTD 只作为受限结构声明放行，不执行 DTD 验证、默认值应用或任何外部资源解析。
