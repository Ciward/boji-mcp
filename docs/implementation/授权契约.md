# Boji 授权契约

更新：2026-11-26。实现文件：[src/auth.ts](../../src/auth.ts)，测试文件：[tests/auth.test.ts](../../tests/auth.test.ts)。

## 入口和边界

- `createAuth(app, db, { publicUrl, publicUrlAliases?, adminPassword })` 必须在全局 `express.json({ limit: '2mb' })` 和 `express.urlencoded({ extended: false, limit: '32kb' })` 之后调用。
- `publicUrl` 必须是 HTTPS 根 origin；开发时允许 `http://localhost`、`http://127.0.0.0/8` 或 `http://[::1]`。它不能含路径、查询、片段、通配符、用户名或密码。
- `publicUrl` 先用 URL parser 规范化成 origin（例如去掉配置中的根路径末尾斜杠），以下 `PUBLIC_URL` 均指这个规范值。默认 MCP 资源为 `PUBLIC_URL + '/mcp'`。`publicUrlAliases` 仅接收显式配置、与主域名使用同一协议的可信根 origin；不从 Host、转发头或数据库中的授权自动加入别名。授权资源必须与当前请求域名的 `/mcp` 逐字相等；token 请求只接受主域名或别名的确切 `/mcp`，并保持原 code/grant 的 resource 绑定，不能带额外末尾斜杠或改绑新域名。
- Web API 只接受 HttpOnly 会话 Cookie，不能使用 Bearer 访问 `/api/v1`。HTTPS 使用 `__Host-boji_session`、`Secure`、`SameSite=Lax`；loopback HTTP 使用 `boji_session`。
- `createAuth` 返回 `requireSession`、`requireCsrf`、`requireMcp`。成功后分别设置 `res.locals.session`，或 `res.locals.auth = { scopes: string[], clientId: string }`。
- `requireMcp` 只验证认证 token、过期时间、resource/audience、client/grant 绑定和已登记 scope。业务工具必须继续检查 `res.locals.auth.scopes`，例如写操作需要 `health.write`。

## Web 会话

- `GET /api/v1/session` 返回 `{ authenticated: true, csrf_token }`；未登录为 `401`。
- `POST /api/v1/login` 只接受 JSON `{ password }`，要求 `Origin` 与当前请求的可信域名同源；不同别名之间也不允许跨源提交。密码使用 `scrypt` 校验；数据库只保存 `scrypt$<salt>$<digest>`。
- 登录成功创建新会话并轮换旧会话。会话默认 12 小时，匿名授权浏览器会话 10 分钟。
- Web 写请求要经过 `requireCsrf`，并同时满足同源 Origin、非跨站 `Sec-Fetch-Site` 和 `X-CSRF-Token`。`POST /api/v1/logout` 删除会话及其待处理授权。
- 登录失败和授权页登录共用持久化限流：单 immediate peer 15 分钟最多 10 次，服务总量最多 60 次。实现不信任 `X-Forwarded-For`。

## DCR 与回调

`POST /oauth/register` 是公开 DCR 入口，支持公共客户端和使用表单密钥的客户端。

- 支持 `token_endpoint_auth_method: none` 和 `client_secret_post`。两类客户端使用 `authorization_code`，可选 `refresh_token`。`client_secret_post` 的随机密钥只在 HTTP 201 注册响应中返回，数据库保存 SHA-256 hash。
- redirect URI 必须精确字符串匹配：HTTPS 任意合法 origin，或 HTTP loopback；禁止 wildcard、fragment、用户名密码、反斜杠和预置 `code`/`state`/`error`/`iss` 查询参数。
- 保存客户端提交的 `client_name`、redirect URI、scope 和 grant type。不读取 `client_uri`、logo 或任何远程 metadata URL，因此不会发生 SSRF 或未验证远程注册。
- 注册和授权请求分别受持久化限流保护。公共客户端保存在 `auth_clients`，要求密钥的客户端保存在独立的 `auth_secret_post_clients`。两类注册均保留于密码或域名变更后。旧版程序只识别公共客户端表。

## Authorization Code + PKCE

GET `/oauth/authorize` 要求：

`client_id`、`redirect_uri`、`response_type=code`、`resource=publicUrl+'/mcp'`、`code_challenge`、`code_challenge_method=S256`；`scope`、`state` 可选。请求 scope 必须是客户端注册 scope 的子集；省略时使用客户端已注册的 scope，并在授权页完整显示后等待用户同意。`health.full` 等效于同时请求 `health.read` 与 `health.write`，授权页列出两项能力。显式 `health.read` 只产生只读授权。仅为所有回调都属于 Gemini 自定义应用 HTTPS 中转地址的 `client_secret_post` 客户端，在主域名可省略 `resource`，服务端以主域名的确切 `/mcp` 作为授权资源。

授权页显示客户端名、回调 origin、完整回调地址、resource 和请求 scope。所有动态文字 HTML 转义；CSP 禁止脚本，form 的 action 固定指向本站；`form-action` 额外允许已登记回调的 origin，因为 Chromium 也检查 303 的跳转目标。回调 hostname 使用安全字符检查，不能注入 CSP 指令。授权页采用 `Referrer-Policy: same-origin`：保留本站 POST 的 Origin，同时禁止向外部回调发送 Referer。实测 `no-referrer` 会使 Chromium 的原生 form POST 携带 `Origin: null`；严格同源检查保持不变，不接受 null Origin。浏览器先获得匿名短会话，提交时用会话绑定的 CSRF token；未登录时必须输入管理员密码。用户必须明确点击同意或拒绝。

POST `/oauth/authorize` 只接受同源 form。审批记录是 10 分钟、一次性的 `auth_pending`，绑定浏览器会话、client、redirect、scope、resource 和 PKCE challenge。审批成功创建 5 分钟一次性 code；拒绝只回调 `error=access_denied`。两类回调都带与原授权请求所绑定资源一致的 `iss`，并保留 `state`；跨域名重放 consent 会被拒绝。未登记的 redirect、错误的 resource 或 scope 不会重定向浏览器。

## Token、刷新和撤销

`POST /oauth/token` 只接受 `application/x-www-form-urlencoded`，按注册方式校验表单密钥，沿用上面的 `resource` 规则。

- `authorization_code` 必须同时绑定 client、redirect、resource、scope 和 `S256(code_verifier)`；任何错误都不会重定向，code 只在数据库事务中标记一次使用。
- access token 有效期 1 小时；refresh token 有效期 30 天。数据库只保存 SHA-256 token hash。
- refresh 请求会撤销该 grant 的旧 access token。常规客户端每次轮换 refresh token，旧 refresh token 重放会撤销整个 grant。满足上述 Gemini 回调和密钥条件的客户端保留原 refresh token 并将到期时间续期 30 天。两类客户端都只能请求当前 token 权限的子集。
- `POST /oauth/revoke` 按登记的客户端认证方式校验请求，对同一 client 的 access/refresh token 撤销整个 grant。未知 token 按成功处理，便于幂等清理。
- `/mcp` 的失败响应为 `401` 或 `403`，带 `WWW-Authenticate: Bearer resource_metadata="PUBLIC_URL/.well-known/oauth-protected-resource/mcp", scope="health.read health.write"`。首次无凭证发现不附 `invalid_token`；已提交但无效的 token 或不匹配 scope 附相应 `error` 和 `error_description`。不读取 query string 中的 access token。
- Boji 的默认用途是读取并记录餐食，因此初次 challenge 申请 `health.read health.write`；必须经过授权页同意后才能签发。已有只读 grant 不会被后台扩大或撤销。
- `tools/list` 对每个工具同时发布顶层 `securitySchemes` 和 `_meta.securitySchemes` 镜像；读工具声明 `health.read`，写工具声明 `health.write`。当前 SDK 1.32.1 的 `registerTool` 不保留顶层扩展字段，因此仅覆盖 `tools/list` 的展示响应；工具输入校验和执行仍使用 SDK 标准注册。
- 有效连接缺少某工具权限时，返回 `isError:true` 和 `_meta["mcp/www_authenticate"]`，包含资源发现地址、`insufficient_scope`、说明以及已有权限与所需权限的并集。客户端可据此重新请求并取得用户同意；不会把权限不足当成 grant 撤销。

## Discovery

- `/.well-known/oauth-authorization-server` 发布 issuer、authorization/token/registration/revocation endpoints、`response_types_supported: [code]`、`grant_types_supported`、`token_endpoint_auth_methods_supported: [none, client_secret_post]`、`code_challenge_methods_supported: [S256]`、`scopes_supported` 和 `authorization_response_iss_parameter_supported: true`。
- `/.well-known/oauth-protected-resource` 与 `/.well-known/oauth-protected-resource/mcp` 都发布确切 resource、`authorization_servers: [当前可信请求 origin]`、支持 scope 和 `bearer_methods_supported: [header]`。
- `client_id_metadata_document_supported` 明确为 `false`；本实现使用 DCR，不访问客户端提供的远程 metadata。


## 密钥、持久化和生命周期

- setup 负责生成并保管 `.env` 中的随机 `ADMIN_PASSWORD`。明文配置需 16–1024 UTF-8 字节；也接受 `scrypt$<32位小写hex salt>$<128位小写hex digest>`，参数为 `N=16384,r=8,p=1`，salt 按 hex 解码，结果为 64 字节。配置中没有内置默认密码。
- `auth_settings` 保存 issuer 和密码验证值；`auth_sessions`、`auth_pending`、`auth_codes`、`auth_grants`、`auth_access_tokens`、`auth_refresh_tokens`、`auth_clients`、`auth_secret_post_clients`、`auth_rate_limits` 保存授权状态。code、session、access/refresh token 只持久化 SHA-256 hash；CSRF 根据原始随机 session token 派生，不由数据库中的 session hash 派生。
- 登录密码使用异步 scrypt，初始化才使用同步 KDF。匿名 pending 为 10 分钟、code 为 5 分钟、认证会话为 12 小时。常规 refresh 家族总寿命为授权后 30 天。符合条件的 Gemini 客户端从最近一次有效刷新再续期 30 天。临近家族到期的 access token 也会缩短。
- 未声明 `grant_types` 的 DCR 按协议默认只授权 `authorization_code`；需要刷新时注册 `grant_types: ['authorization_code','refresh_token']`。
- 正确绑定的 code 重放会撤销已发放的 grant。已轮换的 refresh 重放会撤销整个家族。并发提交在 SQLite 同步事务内检查并消费，单次 pending 或 code 只使用一次。
- 管理员密码改变后，下次初始化仍清空旧会话、pending、code、grant 和 token；登记客户端保留。仅修改公开域名不清空授权数据。若密码未改变且原 issuer 未出现在新主域名或显式别名中，初始化会在修改授权数据前报错，要求明确保留原域名。
- 新旧域名并行时，发现文档、MCP challenge 和授权回调按当前可信 Host/原资源返回一致 issuer；转发头不能改写 issuer。已存在的会话、pending、code、grant、access/refresh token 保留原绑定，正常过期、轮换重放检测和撤销规则继续生效。浏览器 Cookie 仍是 host-only，旧域名登录不会自动转移成新域名登录。退出 Web 会话只清会话，已授权 MCP 客户端通过 revoke 独立撤销。
- 注册限制为每 immediate peer 每小时 20 次、全局 100 次；授权 GET 为每 peer 每分钟 60 次、全局 600 次。429 返回 `Retry-After`。限流使用 SQLite，重启不会复位；代理部署下同一代理连接共享 peer 限额，不采信任意 forwarded IP。
- 授权请求出现时按分钟清理过期瞬态状态，已使用 refresh hash 保留到家族到期以检测重放。`auth_*` 表应随业务 SQLite 一起备份；日志不得输出密码、Cookie、code、verifier 或 token。
- discovery、register、token、revoke 支持不带 credentials 的 CORS/preflight。Web 会话与 consent 不开放跨源 Cookie API。外围 app 若另有 Origin/Host 限制，需要继续遵守其部署约束。

## 官方依据与验证范围

1. [OpenAI Authenticate users](https://developers.openai.com/plugins/build/auth)：原 Apps SDK auth 地址当前重定向到 Plugins；确认 DCR 仍支持，S256、resource/audience、discovery 和 issuer-response metadata 的要求。
2. [MCP Authorization，2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)：当前 `latest` 的目标。DCR 已归入向后兼容路径；本实现按本次范围使用 DCR，明确不宣称 CIMD 能力。
3. 协议关联：OAuth 2.1、RFC 7591（DCR）、RFC 7636（PKCE）、RFC 8707（resource indicators）、RFC 8414（AS metadata）、RFC 9728（protected resource metadata）、RFC 9207（issuer response）。实现以本次单用户边界为准，不提供 OIDC、ID token、多用户或 federation。

认证日志输出 `boji.auth` 结构化事件，区分无凭证、访问令牌过期、授权撤销、绑定失败、工具权限不足和 token 签发/刷新。只输出固定原因、权限、状态和不含查询参数的认证路由；不记录密码、Cookie、client ID、code、verifier、token 或健康记录正文。

`tests/integration.test.ts` 额外覆盖从匿名 challenge 取得读写 scope、真实网络工具权限描述、隔离测试库中的 access token 过期后 SDK 自动刷新且不触发交互授权、刷新后继续写入、只读工具拒绝写入但保持读取和原 grant 有效。

`tests/auth.test.ts` 使用真实临时 HTTP 端口及 SQLite：登录/退出、Origin/CSRF、cookie 属性、持久化重开、限流、注册 URI、同意/拒绝、XSS 转义、授权码绑定和一次消费、access/refresh 过期与撤销、降权和重放、并发请求。Chromium 回归使用真实 form 点击和跨 origin callback，随后完成 code exchange；测试环境缺少 Playwright Chromium 或 macOS Chrome 时，该单项显式 skip，其余 HTTP 测试仍执行。

## 浏览器授权会话恢复

授权页的待确认请求有效期为 10 分钟。重新打开页面会续期匿名浏览器会话并保持其 CSRF 绑定；剩余时间不足 10 分钟的已登录会话会要求重新登录，不自动延长管理员登录。

浏览器提交遇到会话过期、Cookie 丢失或替换时，仍拒绝该提交，不复用密码或批准决定。HTML 页面提供「重新打开授权页面」入口，重新校验客户端、回调地址、资源、权限和 PKCE，并要求再次确认。表单 action 保留已验证的 OAuth 参数，待确认请求被清理后仍可重新发起；无法恢复的旧表单提示返回客户端重新连接。API/JSON 调用保留原错误格式。
