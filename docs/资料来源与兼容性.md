# Boji：资料来源与兼容性快照

核实日期：**2026-10-19**。这是方案阶段的公开资料与本机源码文档核对，不是对用户账户、手机或服务器的实测。资料更新后，应在接入 Spike 中重新确认。

**2026-10-20 补充核查**：Apple Health 设备授权、系统文件导出、现成 HTTP 桥接、HealthKit 后台频率与 WKWebView；新增 S14。其余宿主能力保持原核实日期。

## 1. 事实、建议与未验证项

- **事实**：下列官方文档或项目自身源码能支持的产品能力。
- **设计建议**：SQLite、模块化单体、业务工具、人工修订与回执契约，由 Boji 方案提出。
- **未验证**：真实账户的后台 Boji 调用、手机上传频率、桥接工具当前价格、部署环境、原图传输和端到端消息送达。

不能把官方文档支持、在聊天里能调用、后台任务能调用、真实数据完整、消息成功送达合并成一个“已经支持”。

## 2. Agent 与 MCP

### S01：ChatGPT 定时任务

- [ChatGPT Learn：Scheduled tasks](https://learn.chatgpt.com/docs/automations)
- [OpenAI Help：Scheduled tasks in ChatGPT](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)

Learn 当前说明 Web 定时任务可使用聊天中的上传上下文、已连接工具、skills 和 plugins，并说明聊天内任务可按分钟间隔运行。Help 对部分常规 Tasks 形态另有频率/功能限制，不能混写成所有模式统一支持。Boji 选定真实账户模式后，要验证自定义工具在无人值守运行中的可达性和频率；云端运行不能直接访问本机目录，需经已授权服务。

### S02：ChatGPT 自定义 MCP/Plugin 接入

- [OpenAI Developers：Connect and test your plugin](https://developers.openai.com/plugins/deploy/connect-chatgpt)
- 旧 Apps SDK 地址目前重定向到上述 Plugin 文档。

文档支持通过开发/测试路径接入自定义 MCP 服务；具体入口、账户权限及工作区管理策略以实际界面为准。本项目不写死一个可能过期的套餐兼容性断言，也不将交互接入等同于后台运行验收。

### S03：Claude 连接器与定时任务

- [Claude：Schedule recurring tasks](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork)
- [Claude：Getting started with custom connectors using remote MCP](https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp)

当前定时文档说明可以使用连接器、skills 和 plugins，新任务远程运行；同时保留部分 10 月 6 日以前任务的本地运行说明。Web、统一 Claude 体验、旧 Cowork、本地历史任务需要区分。Boji 仍须用当前账户验证，不假设每份历史聊天或本地附件都能被定时任务访问。

### S04：OpenClaw 原生 automation

- [OpenClaw：Automations](https://docs.openclaw.ai/automation/cron-jobs)
- [How automations work](https://docs.openclaw.ai/automation/cron-jobs/how-it-works)
- [Payloads](https://docs.openclaw.ai/automation/cron-jobs/payloads)
- [Schedules](https://docs.openclaw.ai/automation/cron-jobs/schedules)
- [Delivery](https://docs.openclaw.ai/automation/cron-jobs/delivery)

本轮还直接核对了本机 `openclaw/docs/automation/cron-jobs/` 下同名源码文档。其设计包括 Gateway 常驻、持久运行记录、agent/script/command 任务、显式 MCP allowlist，以及交付 unknown 状态。**这些是所读源码文档的能力，不代表已安装运行时和配置逐项已验证。** 推荐用实际 `--help`、工具 schema 与一次试跑确认，避免复制旧命令。

### S05：MCP 传输与授权

- [MCP：Transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
- [MCP：Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)
- [MCP TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk)

Streamable HTTP、工具/资源与授权是通信能力，不是通用的周期调度和跨产品消息推送服务。协议版本与 SDK 稳定版本在实现时协商/锁定；资源授权、传输会话和用户业务身份分别管理。

## 3. Apple Health 与桥接

### S06：设备端权限与隐私

- [Apple：About the HealthKit framework](https://developer.apple.com/documentation/healthkit/about-the-healthkit-framework)
- [Authorizing access to health data](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)
- [Protecting user privacy](https://developer.apple.com/documentation/healthkit/protecting-user-privacy)

授权按数据类型在设备应用中进行；拒绝读取与数据为空不能简单区分，历史授权也可能仅覆盖有限时间。锁屏可阻止读取。服务器接收权限不能代替设备 HealthKit 授权；没有在本轮取得个人 HealthKit 访问权限。

### S07：增量、更新与删除

- [Apple：Executing observer queries](https://developer.apple.com/documentation/healthkit/executing-observer-queries)
- [HKAnchoredObjectQuery](https://developer.apple.com/documentation/healthkit/hkanchoredobjectquery)
- [HKDeletedObject](https://developer.apple.com/documentation/healthkit/hkdeletedobject)
- [Apple：Manage Health data and sources](https://support.apple.com/en-us/108779)

Observer 通知变化后仍需查询数据；anchored query 能读取新增和删除及新 anchor。删除信息不保证无限期保留。多设备来源需考虑优先级，不能简单相加；XML、聚合导出和样本级桥接也不是天然互斥的数据。

### S08：后台执行和频率

- [Apple：enableBackgroundDelivery](https://developer.apple.com/documentation/healthkit/hkhealthstore/enablebackgrounddelivery(for:frequency:withcompletion:))
- [BGTaskRequest.earliestBeginDate](https://developer.apple.com/documentation/backgroundtasks/bgtaskrequest/earliestbegindate)

后台交付频率和最早启动时间不构成准点交付保证。Apple 文档以步数为例说明后台通知最高为每小时一次。首版把 30 分钟落实为巡检目标，原生 companion 也不能消除系统约束。

### S09：文件导出与现成 HTTP 桥接候选

- [Apple：Share your health data / Export All Health Data](https://support.apple.com/guide/iphone/share-your-health-data-iph5ede58c3d/ios)
- [Health Auto Export：REST API](https://help.healthyapps.dev/en/health-auto-export/automations/rest-api/)
- [Health Auto Export：Automations limitations](https://help.healthyapps.dev/en/health-auto-export/automations/)
- [Health Auto Export：Health metrics format](https://help.healthyapps.dev/en/health-auto-export/export-format/health-metrics/)

Apple 手动导出适合历史初始化。Health Auto Export 文档提供 JSON/CSV、HTTP POST 和认证请求头，明确受锁屏/后台限制。其统计桶、原生样本 ID、来源字段与删除能力须按实际版本和载荷验收；本轮未安装、购买或授权该 App。费用未核实，不写具体价格。

### S14：原生健康访问与复用 Web 前端

- [Apple：Configuring HealthKit access](https://developer.apple.com/documentation/xcode/configuring-healthkit-access)
- [Apple：WKWebView](https://developer.apple.com/documentation/webkit/wkwebview)

官方文档说明，应用集成 HealthKit 需要配置 capability、用途说明和数据类型授权；WKWebView 可在原生应用 UI 中呈现交互式 HTML/CSS/JavaScript 内容。结合 S09，使用 Apple Health 数据不要求自己开发 App，可以先导出文件或使用已实现桥接的 App。

“纯 Safari/PWA 不直接读取 HealthKit”是基于上述公开原生 API 与授权边界的架构判断；本轮没有进行浏览器/真机验证。“SwiftUI + HealthKit + WKWebView 共享前端”是 Boji 的建议方案，非 Apple 对本项目的认证或现成实现。签名、分发、Web 会话和后台同步需要后续独立验收。

## 4. 营养数据

### S10：USDA FoodData Central

- [API guide](https://fdc.nal.usda.gov/api-guide/)

提供标准食品搜索与详情查询，是候选参考数据源。数据库匹配并不证明照片中的食物重量、用油和实际摄入；食物、份量与配方仍需独立保存。本轮不把外部数据库接入设为每次记录的前置条件，也没有申请或使用 API Key。

## 6. 本机 DevSpace 文档核对

本轮读取了同机 DevSpace 的 `AGENTS.md` 和 `docs/artifact-exchange.md`：开发执行层与健康业务权限分开，原生文件下载是可配置能力。未验证远程开发机服务状态，也未把该功能视为所有 MCP 宿主都可用的通用文件接口。

## 7. 讨论与实现前需要实际验证的清单

1. 当前 ChatGPT/Claude 账户的交互和后台工具权限分别是什么。
2. 选定 Agent 的 30 分钟任务能否保存、运行、访问 Boji 并正确静默/通知。
3. 原图能否从选定 Web 宿主转存；不能时结构化入库仍可成立。
4. 实际 Apple 导出/推送载荷有无原生 ID、删除事件、时区和统计粒度。
5. 多来源同一测量进入系统时采用哪条主路径，避免 raw 与 aggregate 双计。
6. 服务器域名、存储目录、认证与备份位置，以及 Web 在手机上的访问方式。
7. 开源许可证、依赖与数据来源许可，在复制/发布前确认。

本轮没有执行这些接入动作；它们是下一阶段的验证工作，不是尚未完成的本轮文档修改。
